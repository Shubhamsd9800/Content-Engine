The Content Engine

How an idea becomes a published post. The architecture, the seven skills, the contract between them, and exactly where the build stands today.

The model has the capability. The input layer is the bottleneck.
There should be a feel that a human is in the loop.

Three layers

Layer 1 — slow, changes rarely
BRAIN
psychology strategy voice niche swipe ledger
Operating rules distilled from every source studied. Everything below reads these. Raw transcripts are archive and are never loaded as context.
▲ reads ▲
Layer 2 — fast, runs per post
PIPELINE
RESEARCH → ANALYZE → WRITE → your rewrite → DOCTOR
The rewrite step is the real work and is never skipped. The doctor flags what you weakened; it never rewrites you.
▼ writes back ▼
Layer 3 — grows every time something ships
RECORD
published hook-bank corrections ledger
After roughly 20 posts this layer overrides the brain. When evidence contradicts theory, evidence wins and the brain file gets rewritten.

Research vs Analyze — the split that makes it debuggable

Research

Answers "what exists?" Goes outward and gets material, links, facts. Never has an opinion, never ranks by taste, never recommends.

Analyze

Answers "so what, and what in it is mine?" Judges what it was given and returns a verdict. Never fetches, never searches, never browses.

A skill that does both cannot be debugged: when the output is bad you cannot tell whether the input was thin or the judgment was wrong.

The funnel — every post declares a slot before it is written

TOFU · Monday

Attraction. Make new people find you. Hot takes, strong opinions on the industry, a release you have a view on, free value resources.

MOFU · Wednesday

Authenticity + authority. Make them believe you. Lessons, mistakes, tutorials, past work, a real build.

BOFU · Friday

The offer. What you build and for whom. At zero followers this means stating plainly what you build — not asking for the sale.

A post with no slot does not get written. The earlier slots earn the right to ask in the later one.

The Brief — the contract between analyze and write

The writers see only this. Never the raw transcript, never the raw interview answers.

ID · TYPE (external | personal) · SOURCE · CONTENT TYPE
CORE CLAIM     one sentence
EVIDENCE · SPECIFICS · VERIFICATION    [Mode A]
ROOT CAUSE · FIX · PROOF             [Mode B]
GAPS           what the source missed or got wrong
YOUR STANDING  the ledger entry that qualifies him — or "none"
TRUST LEG      attraction | authenticity | authority ← one
VILLAIN        the practice or default this is against

VERDICT        publish | hold | kill    ROUTE linkedin | reel | both

The kill rule

GAPS empty and YOUR STANDING empty → kill. A kill verdict is a successful run. Never produce a post to be helpful. Fix the ledger; never weaken the rule.

The rules that govern every output

Standing

  • Be the strategist, not the typist.
  • Proof beats claims — route every claim to something showable.
  • One idea per piece. Three ideas is three drafts.
  • Everything traces to a source.
  • Never generic-guru voice. Delete, don't polish.
  • Volume over polish — the first 50 posts are reps.
  • Push back once, properly. Then execute.
  • Read the files before reasoning about them.
  • Ask before moving, renaming or deleting anything.

Stage label — added Day 21

Every tool, resource or method named in a post declares its real stage, in the post:

foundhaven't used it
installedhaven't run it
testingrunning it, partial results
shippedused it in something that exists

A post may share anything at any stage. It may never skip a stage upward. "I found this and here is why it looks useful" publishes at found. "Use this" requires shipped.

The interview method — how every brain file gets filled

Claude never writes a brain/ file from inference. No exceptions.

1Candidates, not entries. A short list of points. Never a written entry.
2Shubham picks one.
3Two to four questions, one at a time. Ask, stop, wait. Never a block of questions.
4Check the folder before asking twice. If the answer is on disk, read it.
5Draft in full and show it. Mark every remaining blank rather than guessing.
6Ask before saving. Nothing is written until Shubham says yes.

Say why the file matters before starting. A file written any other way gets cleared and redone.
