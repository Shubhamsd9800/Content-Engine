# queue.md — candidates, not decisions

**Written by:** `topic-scout` (RESEARCH — it gathers, it never judges).
**Read by:** Shubham, then `brief-builder` on whichever line he picks.

> **Nothing in this file is a decision.** A line here means *"this exists and it is in the
> right neighbourhood."* It does not mean it should be posted. `brief-builder` decides that,
> and a kill is a successful outcome.

**Ring is a suggestion, not an assignment.** `brief-builder` assigns the real ring after
reading the last six entries of `work/log/published.md`, because the mix is arithmetic over a
series and only that file knows the series.

---

## HOW A LINE MOVES

```
topic-scout finds it      →  QUEUE
Shubham picks one         →  brief-builder
brief-builder decides     →  publish · hold · kill
                          →  line moves to USED or KILLED with the reason
```

**Prune anything older than 14 days.** A trending item that sat for two weeks is not trending,
and a queue nobody prunes becomes a guilt list.
