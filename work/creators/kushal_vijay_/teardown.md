**#12, verbatim, is six sentences with one frame:**

```
If you want to learn RAG,        then build this project.
If you want to learn agents,     then build this project.
If you want to learn evals,      then build this project.
If you want to learn fine tuning, then this project has to be in your resume.
If you want to learn LLM ops,    then build this project.
If you want to learn guardrails, then build this project.
```

**This is NOT S03's step list and the difference matters.** S03's body is **sequential** — do
step one, then step two, and all three steps are for the same viewer. K2's body is **parallel** —
six items, and the viewer only needs the ONE that matches them. Sequential lists retain by
promising completion. **Parallel lists retain by running a lottery: each line is another chance
that this one is about you.** Different mechanic, different retention curve, different failure
mode. S03 fails if a step is missing; K2 fails if the items are too similar to each other.

**⚠️ NOT PROMOTED — and the reason is a defect in the engine, not in the finding.**

The bar is 5 of 10. K2 is a **body** pattern, and body patterns can only be counted across the
three winners, because the control set is captions only. **A body pattern cannot reach 5 of 10 by
construction.** `_BATCH-1-AUDIT.md` §4 flagged this exact limit after Batch 1. This is the second
batch it has bitten. **See `ENGINE DEFECT` at the bottom of this file.**

**What it would take to promote it:** one more creator showing parallel anaphora in their winners,
at which point it becomes a cross-creator finding and the count rule stops being the gate.
`projectonepercent01` and `devtalksbusiness` are both still to be read this batch.

## ── ⚠️ ENGINE DEFECT — raised here, not fixed here ──

**A body-level pattern cannot clear the 5-of-10 promotion bar, ever, by construction.**

The control set is captions only, truncated at 100 characters by OpenCLI. Only the three winners
have transcripts. So any pattern that lives in the body of a piece can be counted across **at most
3**, and the bar is **5**. Flagged in `_BATCH-1-AUDIT.md` §4 after Batch 1; it has now blocked a
real finding (K2) in Batch 2.

**Three options, none taken here:**
1. Run a **separate bar for body patterns** — e.g. 3 of 3 winners AND a second account.
2. Transcribe part of the control set. Expensive; A6 is manual.
3. Accept it and let body patterns promote only as **cross-creator** findings (rules, not shapes).

**Option 3 is what the engine is already doing by accident.** Making it deliberate costs nothing
and would have let K2 through as a rule. **Shubham's call.**
